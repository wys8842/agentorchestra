## M2. 存储层（`memory/storage.py`）

**任务**
- `BaseMemoryBackend.iter_all(self, namespace: str = "default")`：抽象方法加 namespace 参数
- `InMemoryBackend.iter_all(ns)`：过滤 `entry.namespace == ns`
- `JsonlBackend.iter_all(ns)`：同上
- `SqliteBackend`：
  - `_ensure_schema()` 用 `PRAGMA table_info(memories)` 检测 namespace 列，缺则 `ALTER TABLE`
  - `CREATE INDEX IF NOT EXISTS idx_memories_namespace ON memories(namespace)`
  - `upsert(entry)` 语句包含 namespace 列
  - `iter_all(ns)`：`SELECT ... WHERE namespace = ? ORDER BY updated_at DESC`
- 保持 `all()` 向后兼容（默认 `namespace="default"`）

**验证**
- 新建 v1 数据库（无 namespace 列），启动 SqliteBackend → 验证迁移成功，列被加上
- 写两条不同 namespace 的 entry → iter_all("default") 只返回 default 一条
- 写一条 entry.namespace="default"，iter_all() 返回它

## M3. 检索层（`memory/index.py`）

**任务**
- `_compute_decay(updated_at_iso, importance, now, tau_min, tau_max) -> float`
- `HybridRetriever.__init__` 不变（参数在 recall 传入）
- `HybridRetriever.recall` 新签名（默认 `namespace="default"`）
- 在 recall 内：namespace 过滤 → 类型过滤 → 向量精排 → 融合归一化 → 衰减打分（仅当 `decay_enabled=True`）→ top_k → entry.touch() 强化
- 添加 `from datetime import datetime` 解析 updated_at

**验证**
- 衰减公式单测（重要性 1.0 / Δt=0 → 1.0；重要性 0 / Δt=14d → 0.5）
- `recall(decay_enabled=False)` 时分数与 v1 一致
- `recall(decay_enabled=True)` 时老条目分数被压低
- recall 命中后 entry.updated_at 已被刷新

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| SQLite ALTER TABLE 失败（v1 数据残留问题） | 用 PRAGMA 检测后再 ALTER；失败仅 warning 不致命 |
| namespace="default" 过滤老数据不命中（迁移前数据） | 迁移时 `DEFAULT 'default'`，老数据自动归入 default |
| 衰减参数不直观导致效果差 | 默认值（7d / 180d）参考 Ebbinghaus，文档说明 |
| HybridRetriever 召回时 namespace 过滤后候选不足 | 正常返回 top_k；若全部被过滤则返回空列表 |
